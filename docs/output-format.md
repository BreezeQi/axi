# 输出字段定义与查看

`output_schema` 是正常成功业务结果的字段文档，用于搜索和查看，不校验、补齐或裁剪工具返回值。
注册方提供选定的正常结果模型，保证层级、类型、含义和单位准确；无需为错误返回声明 `Success | Error`。
正常业务中的故障码、告警、失败数量等仍是普通字段，不按名称排除。
推荐使用字段明确的 Pydantic 2 模型、嵌套模型和记录数组；动态字典工具可以省略定义。

原生 Python 工具通过 `@tool(output_schema=...)` 提供 Pydantic 模型类或 JSON Schema 字典。
外部 MCP 工具连接时优先读取工具清单的 `outputSchema`，否则读取 `_meta["axi/output_schema"]`。
Pydantic 使用 serialization 模式转换，JSON Schema 字典直接沿用，统一保存为 AXI 内部的 `output_schema`。

AXI 不为工具注入运行时 `output_fields` 参数，也不提供结果裁剪 API。
工具调用只接受其业务签名声明的参数；自行定义的 `output_fields` 仍作为普通业务参数。
`describe` 响应中的 `output_fields` 是文档字符串，不是实际业务数据或运行时裁剪功能。

模型可依据字段文档先编写脚本，在分析前保存原始调用结果。结构不匹配时，读取已保存的数据并修改分析逻辑，
通常无需重新请求上游；这属于模型的工作方式，AXI 不新增自动落盘、业务结果缓存、成功分支识别或脚本重试。
实际收益需要实测，不预设工具调用次数必然减少。

## 字段文档

`matched_fields` 是字符串数组，每条为 `JSONPath: 类型；自身说明`；无说明时只写类型，无字段命中时为 `[]`。
文档同时是检索文本与返回摘要，由 BM25、可选 Embedding、grep 共用，查询不再解析 Schema 或构造查看树。
检索按条目判断相关性，命中后完整返回该条目的紧凑释义，不按查询裁剪内部组合分支。
同工具完整文本完全相同的条目在准备时去重，后续直接沿用；同路径不同类型或说明分别保留，不同工具保留各自归属。
不合并大小写、近义说明或 description 内部的重复词语。

| 声明位置 | 路径示例 |
| --- | --- |
| 对象属性 | `$.speed` |
| 对象数组属性 | `$.vehicles[*].speed` |
| 根数组的标量元素 | `$[*]` |
| 固定元组位置 | `$.position[1]` |
| 固定前缀后明确声明的元素模板 | `$.position[2:]` |
| 字面名称 `a.b` | `$["a.b"]` |
| 字面名称含空格、引号、反斜线 | 使用带方括号的 JSON 字符串名称选择器 |

只枚举 Schema 声明的对象属性、元素模板和固定位置，包括标量元素，不按实际长度生成逐项文档。
数组层级显式保留，路径中不加入 `properties`、`items`、`anyOf` 或 `$defs` 等定义位置。
组合的结构分支各自枚举，例如对象分支的 `$.payload.value` 与数组分支的 `$.payload[*].value` 分别保留。
同路径不同声明可以是 `$.payload.value: str；标签` 和 `$.payload.value: float；重量`，不混拼含义。
普通数组及元组元素各自使用自身说明，不向上追加到容器；无说明节点只保留类型。
字段文本不重复拼入各级键名或祖先说明。父节点命中不自动包含后代；后代自己的路径或说明匹配时正常返回。
约束参数不转换成文案，业务含义、单位和必要范围由作者写入对应节点的 description。

## search 检索

### 目录边界

search 保留各入口 v0.0.13 的目录范围与 K 含义：

| 入口 | 检索目录与数量 | 可选 Embedding 范围 |
| --- | --- | --- |
| CLI | 本地 Native 与 daemon MCP 分别取最多 K 个，Native 在前拼接，最多 2K | MCP 目录；Native 保持 BM25 |
| MCP meta | Native、MCP 合并目录，整体最多 K 个 | 整个合并目录 |
| Python Registry | 自身持有的目录，整体最多 K 个 | 依自身配置作用于整个目录 |

多个 MCP server 共用 daemon 目录及名额，不按 server 分别取 K。来源只决定入口持有的目录，Registry.search 不强制拆分混合来源。
两份 CLI 目录之间不比较分数或做 RRF；某目录为空时只返回另一目录，不转移名额。
例如 K=2，CLI 的 Native 命中 `N1、N2、N3`、MCP 命中 `M1、M2、M3`，返回 `N1、N2、M1、M2`；
Native 没有命中时只返回 `M1、M2`。MCP meta 在合并目录重新评分、排名，最终整体最多2个，不能以截断 CLI 的拼接结果代替。
CLI 允许相同完整工具名分别返回，实际调用优先 Native；MCP serve 按 Native、MCP 顺序注册，同名由后者覆盖。因此，完整名称冲突时，不保证不同入口使用同一定义。

### 双路检索与排名

每份目录内，工具说明与输出字段分成两个独立索引，查询时并行执行，共用分词、BM25、可选 Embedding、权重与 RRF：

- **工具路**：只索引完整工具名＋description，保持 0.0.13 的检索范围；BM25、Embedding 各取前 K 条工具候选后融合，再推荐前 K 个工具。
- **字段路**：沿用 Schema 生成的字段文档；读取全部命中后融合，每个工具按其最强字段的排名推荐，不按命中字段数量累加分数。Schema 根说明也在这一路检索，不另生成重复的 `$` 字段摘要。

未启用 Embedding 时沿用 BM25 排名。目录启用后，两路均按原始文本名次做相同的加权 RRF，
不按工具归属改变名次，不另设字段评分或权重，也不按工具内部名次再次融合或计分。
BM25 和 Embedding 沿用大于0的分数过滤；精确字面匹配保留现有补齐入口，不新增相关性阈值。
BM25 候选和同分截取沿用 0.0.13 的 bm25s retrieve；Embedding 同分保留文档顺序，RRF 同分保留首次进入融合的顺序。
两路之间不比较原始分数，也不对两路再做 RRF。

### 工具推荐与字段摘要

两路各推荐前 `top_k` 个不同工具，按“工具路第1、字段路第1、工具路第2、字段路第2……”交错，
按完整工具名去重，该目录最多返回 K 个。K=1 时工具路优先，工具路为空时取字段路；
某一路为空则沿用另一路的结果，不足 K 个不补入未命中的工具。并行完成先后不影响交错顺序。
K≤0、空字符串或纯空白查询返回 `[]`，跳过索引准备、Embedding 和远程发现请求。

字段路推荐工具的 Top-K 截断不丢弃其他工具已有的字段命中。M=`search.maxFields`，默认8。
最终每个入选工具都附带它已有的字段摘要，无论从哪一路入选，也不要求它进入字段路前 K 个。
摘要按字段相关性排序，最多 M 条；工具说明和根说明不占字段名额，不要求填满，没有命中返回 `[]`。
M=0 仅隐藏摘要，不影响字段路召回、工具排名或最终工具集合；不为补摘要再次检索。
完整查询精确匹配字段名或 JSONPath 时，沿用字面匹配兜底，优先展示该工具命中的对应节点，
受相同字段数量上限限制，不强制工具置顶。JSONPath 与 describe.fields 共用解析规则，
单/双引号、等价名称选择器和转义写法定位同一声明位置；自然语言查询按普通相关性排序。
不支持的路径表达式仍作为普通检索文本，不新增过滤器或实际数据查询能力。

例如某一目录内 K=3、M=2，工具路为 `X、A、B`，字段命中为 `A.x、B.x、A.y、C.x、X.x、X.y、X.z`。
字段路推荐 `A、B、C`，两路交错得到 `X、A、A、B、B、C`，去重取前三个为 `X、A、B`。
摘要分别为 X 的 `X.x、X.y`，A 的 `A.x、A.y`，B 的 `B.x`；X 未进入字段路前三仍附带摘要，
X.z 超出 M 不展示，未入选的 C 不返回。

### 语料隔离与更新

检索文档变化可以自然改变分数和顺序，不为恢复旧排序添加权重。工具路的 BM25 语料只含工具说明，
增加输出字段不会改变它的语料统计、分数或排名。相同目录、查询、依赖环境和实际配置下，
无 Schema 或字段路没有候选时，工具集合和顺序与发布版 v0.0.13（ce069c3）对应入口一致；
字段路没有候选不能仅凭 matched_fields=[] 判断。
Embedding 初始化沿用原有配置流程，初始化错误直接报告；索引构建（含缓存写入）或查询失败时，报告原因并使用 BM25。

未配置 MCP 时只检索本地目录，不请求或启动 daemon。
远程发现不可用、连接中断、响应行超限或 JSON 解码失败时报告原因并保留本地结果。
定义更新通过重新注册生效，不自动检测字典原地修改；更新与查询应顺序执行。升级或修改 MCP 搜索配置后须重启 daemon。
AXI 不做完整 Schema 合法性检查，注册方负责提供可用定义并保证与输出一致。检索与查看共享字段文档，局部查看不强制枚举全库；内部生命周期见[架构](architecture.md)。

## grep 检索

`grep` 保留忽略大小写的全文正则，在自身目录内按工具登记顺序返回，不使用上述候选和融合评分。
工具内对所有实际匹配条目按数据层级从浅到深稳定排序，再截取 `maxFields`；同层保持声明顺序。
`$` 不计层级，每个属性、元素模板或固定位置增加一层，特殊键名内的点号不增加层级。
不补入未命中的父节点或后代；`search` 仍用相关性顺序。JSONPath 中的正则特殊字符按正常正则转义。
字段使用上述共享文本；工具完整名称、工具 description 和 Schema 根说明仍分别匹配，
`^` / `$` 锚定各自的完整文本，不跨工具名和说明拼接匹配。
grep 使用相同的[目录边界](#目录边界)，数量参数为 limit；上限≤0返回空数组，空正则仍按正则语义匹配。
每个工具最多展示 `search.maxFields` 个命中字段；设为0只隐藏摘要，字段仍能用于检索工具。`describe` 不受这个数量限制。

### 限定工具的字段检索

`search(query, top_k=5, tool="server/name")` 只走指定工具的字段路，CLI 为 `axi search "里程" --tool server/name`，MCP meta 使用同名 tool 参数。
复用当前目录已建立的字段索引及相关性排名，在选取工具和摘要前限定归属，不先截取全局 Top-K 再筛选。
不检索工具名或工具 description，也不改变字段评分、精确名称／JSONPath定位和根说明的现有索引范围。
返回协议仍为摘要数组，最多一个工具；top_k 仍限制工具数，字段展示上限仍为 maxFields，0仅隐藏摘要。
名称沿用已有解析和未知／歧义提示。CLI 优先解析本地工具，未找到才请求 MCP；本地工具字段无命中时返回空数组，不改搜同名远程工具。
grep 保持现有接口。优先利用命中的完整字段说明，只有缺少参数或局部结构时再 describe。

## describe 查看

`describe(name, fields=None, schema=False)` 根据缺少的信息选择查看入参、局部输出或完整定义，字段说明已足够时直接调用，不要求先完成所有发现步骤。

| 调用方式 | 返回内容 |
| --- | --- |
| `describe(name)` 或 `fields=null` | 工具身份、业务说明和完整入参；不准备或返回输出文档与示例 |
| `fields=["$"]` | 输出根节点的一级目录、范围标记及已有示例；不返回入参 |
| `fields=[具体路径, ...]` | 对应位置的输出文档、范围标记及已有示例；不返回入参 |
| `fields=[]` | 空输出字段视图，不返回入参；保留输出定义状态、类型及已有示例 |
| `schema=true`，fields 省略或 null | 工具身份、业务说明、输出定义状态及已登记的完整标准 `output_schema`；不返回入参、紧凑文档或示例 |

`schema` 默认 false，保持所有原有 fields 语义；true 时不能同时指定非 null 的 fields，包括 `[]`，否则返回参数冲突。
CLI 使用 `axi describe server/name --schema`；Python 使用 `registry.describe(name, schema=True)` 或 `describe_many(names, schema=True)`；MCP meta／flat 使用相同的 `schema` 布尔参数。
完整视图中的 `output_schema` 是原生 JSON 对象，保留登记的 `$defs/$ref`、组合、必填、约束、标题、说明及未知扩展，不展开引用、不重新生成定义。
直接读取定义，不依赖字段索引或紧凑文档生成，不执行业务工具；修改返回对象不会影响注册数据或同批其他结果。
未登记时为 `not_registered` 且不附 output_schema，显式 `{}` 为 `registered` 并返回 `{}`。完整定义仅在显式请求时返回，不附带到普通查看、搜索或业务结果。

fields 只影响文档选择，不改变实际工具参数或返回。不提供额外的范围或深度参数。
选中对象展示直接子字段，子容器保持紧凑释义；选中标量展示自身类型和说明。
选中数组保留元素模板和元组位置，展示元素的直接字段；引用与组合不额外增加这一级展开。
例如根目录为 `{rows: list[dict]}`，选择 `fields=["$.rows"]` 返回 `{rows: [{value: float；读数}]}`，元素中的下一层对象仍折叠。
显式深层路径直接可见，祖先仅组织结构。多个路径取并集，子路径不缩小父级选择范围，结果与路径顺序无关。
选择 `$` 仍只展示根下一级；继续查看时选择具体容器。JSONPath 的64层数据位置上限保持不变。
`output_fields` 为面向 Agent 阅读的文档字符串；已登记 Schema 的空选择显示 `"{}"`。
外层响应仍是 JSON，入参模式的 `input_schema` 为完整 Schema；输出模式提供登记状态和路径提示。

按当前缺口选择操作：

| 当前需求 | 操作 |
| --- | --- |
| 不知道使用哪个工具 | `search(query)` 或 `grep(pattern)` |
| 不清楚工具参数 | `describe(name)` |
| 浏览输出目录 | `describe(name, fields=["$"])` |
| 已知工具，寻找指标 | `search(query, tool=name)` |
| 已知路径，查看局部结构 | `describe(name, fields=[path])` |

例如一个工具返回列式分页结果，下面的请求只查看声明的 constants、columns、values：

```json
{
  "name": "fleet/query_carrier_efficiency",
  "fields": ["$.constants", "$.columns", "$.values"]
}
```

CLI 对应 `axi describe fleet/query_carrier_efficiency --fields '["$.constants","$.columns","$.values"]'`。
同时需要入参与输出时，分别调用 `describe(name)` 和 `describe(name, fields=["$"])`，两次请求可并行执行。
输出 Schema 应描述完整正常业务返回，包括实际的 constants/columns/values/page 等层级；不要用解码后的记录代替真实返回。
JSONPath 的 `$` 指向业务返回，不包含 AXI CLI 的外层信封；业务自身的 data/result 字段仍保留。

### 状态、路径提示与批量

未提供输出 Schema 时，返回 `output_schema_status="not_registered"`，不把请求路径标为未知；
已提供时为 `registered`，即使选择零个字段也不变。schema=false 且 fields 省略或 null 时不返回输出相关标记。
路径未知时，`unknown_fields` 返回按 Schema 声明位置规范化的完整 JSONPath，保留未知位置后的剩余路径；
`available_fields` 按最近有效父节点列出下一层已声明的 JSONPath，例如：

```json
{
  "unknown_fields": ["$.summaryStatistic.missing.leaf"],
  "available_fields": {
    "$.summaryStatistic": [
      "$.summaryStatistic.forwardMileage",
      "$.summaryStatistic.backwardMileage"
    ]
  }
}
```

不附带整个输出目录，不猜测或自动改名；最近父节点没有子位置时给出空列表。
元组通配的未知路径可能按适用声明具体化为固定位置或尾部路径：例如 `$[*].missing` 可返回
`$[0].missing`、`$[1].missing`，已声明的尾部使用 `[n:]`。通配路径在任一适用声明中命中即视为已知；
显式固定位置和尾部选择独立判断，不因通配命中而隐藏错误。
批量工具名用逗号分隔，单项名称或文档生成错误仅影响该项，其余项照常返回。
名称或文档错误以 `{"error": "..."}` 返回；CLI 单工具失败退出码为1，批量保留逐项结果。MCP describe 沿用结果文档中的 error 提示，不将该项转换为协议错误。
CLI 本地未找到且配置了 MCP 时，逐工具请求 daemon；未配置 MCP 时直接返回未找到，不请求或启动 daemon。

### JSONPath 字段选择

`fields` 使用 JSONPath 数组，直接复用搜索命中的路径，不传类型和说明。
支持属性、数组模板 `[*]`、元组固定位置 `[n]` 和已声明的尾部 `[n:]`；特殊键使用 `$["a.b"]` 或 `$['a.b']`，引号和反斜线按名称字符串转义。
位置只匹配 Schema 声明：普通数组不生成 `[0]` 等实际索引，不支持过滤、递归下降、属性通配或一般切片。
不接受分组对象或裸字段名。元组通配与固定位置的子选择取并集：
`["$.position[*].a", "$.position[0].b"]` 在第 0 项同时保留 a、b；显式尾部 `[n:]` 同理。
数组展示的是定义模板，不代表实际元素数量。普通数组展开为 `[元素释义]`，包括标量元素的自身说明。
元组展开时保留声明位置标签：`[[0]: float；纬度, [1]: float；经度]`；已声明的尾部标为 `[n:]`。
仅选择 `$.position[1]` 时显示 `{position: [[1]: float；经度]}`，不将其重编号为0，也不补未选位置。
折叠时仍汇总元素类型；父级展开和 `[*]` 选择均按声明顺序保留各位置，不归并不同位置的字段。

### 结构与组合展示

显式路径仍可进入自动递归保护已折叠的分支。对象与记录数组的联合类型中，同一位置可能对应多个 Schema 节点；
检索按声明分支枚举多条文档。describe 的终点和展开结果统一使用 `anyOf(...)`、`oneOf(...)`、`allOf(...)` 组合术语，保留各分支的对象、数组层级，不把分支字段拼成同一个对象。
例如 `reading` 声明为对象或记录数组，`fields=["$.reading"]` 返回：

```json
{
  "output_fields": "{reading: anyOf({temperature: float；温度}, [{status: str；状态}])}"
}
```

整个视图直接渲染为文本：对象用 `{字段: 子表达式}`，数组用 `[元素模板]`，组合用 `anyOf(...)`、`oneOf(...)`、`allOf(...)`。
例如 `{reading: anyOf(dict, list[dict])；本次读数}` 是一级目录；展开后显示分支结构，不重复父节点说明。
这是阅读用文档，不要求内部文本是 JSON 或 Python，不执行、不解析。
普通字段名直接展示，特殊名复用 JSONPath 名称转义，例如 `{["a.b"]: float, a: {b: int}}` 区分字面名称和层级。
嵌套表达式直接连接，外层 JSON 序列化统一处理引号、反斜线和换行转义。
组合不属于业务数据，不加入 JSONPath，也不增加展开层级。上例取值路径仍是 `$.reading.temperature` 和 `$.reading[*].status`。
真实业务字段即使名为 `anyOf`、`oneOf` 或 `allOf`，也按普通字段展示。仅选择深层路径时只保留适用分支；已选父级范围内的其他分支仍按一级规则展开或折叠。路径在任一适用分支存在即视为已知。
`type` 列表展开时也用 `anyOf` 表示可选形态；对象、数组和 `null` 等类型分别保留，不标成同时满足的 `allOf`。
同一节点的引用与相邻结构声明以 `allOf` 并列展示，不覆盖或归并字段；引用循环不屏蔽本地声明的属性、元素和组合分支。
展开节点展示子结构，未展开节点继续显示紧凑的自身类型和说明，例如 `anyOf(dict, list[dict])`。

## Schema 支持范围

支持本地 `$ref`、对象、数组、可空与组合类型、固定元组。
本地引用按 `#` / `#/...` JSON Pointer 解析，递归索引有界，不联网解析外部引用。
字段路径最多64层，属性和数组位置各计一层，与所选节点的一级展开规则分别处理。
第64层可检索、可选择，查看在该层保留自身释义，不继续展开第65层。
引用与组合包装不消耗数据层级，也不另外按64步截断；长别名链或组合包装仍保留目标声明的类型、说明及子字段，真实引用循环继续按当前引用链保护。
`$anchor`、嵌套 `$id` 的资源跳转和条件分支字段枚举不在发现能力范围内，原 Schema 保留。
Schema 由 Pydantic 2 类按 `serialization` 模式生成，或直接传入 JSON Schema 字典。
字段解析以 Pydantic 2 输出为准，字典沿用相同规则，不按旧草案标记切换文档语义。
终点只格式化已声明的类型与自身说明，不计算类型交集或判断组合是否矛盾。
组合统一使用 Schema 名称：`anyOf(float, None)；车速`、`oneOf(float, str)`、`allOf(str, int)`。
分支说明跟随对应类型，例如 `anyOf(str；标签, float；重量，单位千克)`；整体说明附在组合外。
`anyOf`、`allOf` 逐层按完整释义去重，保留首次声明顺序；展开没有自身说明的同类嵌套，单分支省略包装。
例如 `anyOf(anyOf(float, str), anyOf(float, str))；设备温度` 简化为 `anyOf(float, str)；设备温度`。
不同说明不合并，带独立说明的组合保留分组，description 内部文字不去重。`oneOf` 保留原分支数量与嵌套，显式单分支也保留包装，不套用上述简化；展开查看同样保留分支归属，引用复用或 JSON 序列化不改变分支展示。
不同且有用的内容正常展示，不额外截断、缩写引用或设置大小上限。oneOf 保留重复分支和嵌套，反复引用可能产生较长文档；循环保护不等同于文本长度限制，作者宜避免无意义的重复包装。
折叠释义中的数组元素类型沿用 Python 风格表示，`type` 类型列表仍显示为 `float | None` 等形式。
元组容器汇总各位置的类型并去掉重复类型，例如纬度、经度均为数值时显示 `list[float]`，混合类型显示 `list[str | float]`。
这是容器类型汇总，不是原 Schema 的组合声明；元素内部组合使用相同的释义简化规则。
没有类型声明时显示 `Any`，显式 `false` 显示 `false`；不推导 `Never`、交集或未声明字段的类型。
本地引用独立解析当前终点；递归保护只停止结构继续展开，不影响终点读取已有说明。
引用解析后使用相同简化规则，不因在其他分支出现过就省略；只有当前引用链中的循环或无法解析的引用保留 `$ref(...)`。
同一终点沿引用链读取的完整 description 按首次出现去重，不拆分说明文字，也不跨组合分支合并说明。
仅声明 `properties` 的字段仍可发现；节点自身明确声明非对象类型时，其 `properties` 不贡献字段或说明。
声明 Schema 不改变原生工具签名、参数模型或返回值；AXI 不注入 `output_fields`。
`describe.fields` 只控制文档展示，不筛选真实数据。

字段目录枚举固定属性、数组元素模板和元组位置。`additionalProperties` 的值定义与
`patternProperties` 不参与字段检索、释义或实际键解析；未知键通过
`unknown_fields` 报告。原 Schema 保留，不改写第三方 MCP 的输出契约。

标量数组和固定元组使用容器自身的 description，不把 `items` / `prefixItems` 的说明
追加到容器；元素自己的 description 在对应 `[*]` 或 `[n]` 位置参与检索。
数组数量约束不参与字段文档：`rows: list[Row]` 即使声明 `max_length=0`，仍保留 Row 的属性。
折叠时显示 `list[dict]；历史记录`，展开的文档文本为 `{rows: [{mileage: float；累计里程}]}`。
列表中的对象是元素说明模板，不代表实际返回数量；AXI 不校验该数组的长度。
没有可展开子字段的根对象也作为终点展示类型和自身说明；显式空选择仍返回空定义。

## 返回结果与文档范围

Python/PTC 调用保留原始返回对象，支持同步、异步及 awaitable。声明 `output_schema`
不改变工具执行、错误处理或返回序列化，CLI/MCP 保持原有返回编码：
CLI 使用已有的 Pydantic Python 模式 dump 并省略空值；MCP 返回文本，非字符串使用
`json.dumps(..., default=str)` 编码。字段文档不新增别名转换、JSON 模式 serializer
或显式 null 的传输规则，不通过输出模型校验结果。
列式表、CAN 压缩、多表信封等均作为完整业务结果返回，AXI 不解释其裁剪或元数据保留规则。

CLI 键值对传参通过 `describe(name)` 获取 MCP 入参定义，按原流程解析参数；
查询失败时使用空 Schema，继续由 Executor 执行。显式 JSON 和无参调用不经过入参查询。

可选 `output_example` 沿用各入口原有编码：describe 使用 ToolMeta 的 Python 模式 dump，
默认保留模型字段名并省略模型中的 None 字段，不强制 alias 或 JSON 模式 serializer；字典内的 null 保留。
MCP 平铺工具说明使用 `json.dumps(..., default=str)`，模型对象沿用文字表示。
未提供示例时不生成占位；模型本身序列化为 null 的示例仍保留 `output_example: null`。
fields 省略或 null 时省略输出示例；`fields=[]` 不隐藏已有示例。

JSONPath 的 `$` 固定指向工具正常成功时返回的完整业务值。CLI 的 `status/data/error` 信封不属于该值，
先按调用约定取得外层 `data`；业务自身的 `data`、`result`、`record` 等字段必须保留在路径中。
AXI 不根据名称剥离字段，不自动解码或对真实数据执行 JSONPath。需要减少数据时，使用工具自身的业务
查询参数或在 Python 中处理完整结果。

## MCP 字段文档与调用边界

远程 MCP 的输出 Schema 参与字段发现和 `describe`；是否支持字段选择以其 `input_schema`
为准，AXI 不自动增加选择参数。第三方工具的同名 `output_fields` 参数不改变其契约。
远程调用直接使用 MCP SDK，保留上游已有的 SDK 校验、连接持有和重连流程。AXI 不为字段
文档覆盖 SDK 输出检查，也不追加 null、缺失内容或输出契约错误的特殊分支。
SDK 返回后，AXI 先处理 `is_error`；成功且 `structured_content is not None` 时，直接返回
结构化业务值，包括空对象 `{}`，不合并 `content` 展示文本。未提供结构化结果时，沿用
`content` 提取与单段 JSON 解析；例如文本 `42` 可解析为数字，多段内容保持列表。
该优先级不依赖是否登记输出 Schema，不增加请求、重试或返回校验。

导入时尝试读取远程标准 `outputSchema` 或 AXI 元数据作为字段文档，不做完整 Schema 合法性检查。
文档不是字典时，仅忽略该工具的输出文档并记录原因；保留工具接入与调用，不改写 SDK
持有的上游定义。

导出时，原生及远程工具的字段文档均放在 `_meta["axi/output_schema"]`，不为业务工具新增标准 MCP `outputSchema` 契约。
业务结果沿用已有文本编码，不新增结构化结果、null 恢复标记或旧协议适配层。

flat 模式含输出 Schema 时提供 `axi_describe`，参数与 meta `describe` 相同；`name` 使用
`tools/list` 中的业务工具名，成功结果的 `name` 也使用可直接调用的导出名，不附内部 `server`；
批量错误保留请求使用的导出名。客户端无需展示自定义 `_meta` 即可按需查看字段。名称冲突时
追加 `_2`、`_3` 后缀，既有业务工具名稳定。
